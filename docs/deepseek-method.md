# DeepSeek 部分：图文分析与日报提取方法

我把 DeepSeek 相关操作分为两个部分：本地程序调用官方 API 分析文章，独立的 DeepSeek Harness 读取报告并通过其已授权 IM 功能发送消息。两者有不同的输入和职责；Harness 不需要读SQLite、抓取文章或再次调用API分析。我的推送提示词和配置步骤见 [Harness 每日微信推送](harness-push.md)。

模型推理由 DeepSeek 官方 API 提供，本仓库不训练或分发模型权重。保留本地请求、字段校验、错误处理和结果保存的代码，以便复现整个程序；真实 Key、调用原始记录与个人分析结果不随代码发布。

## 请求方式

当前实现使用 `https://api.deepseek.com/chat/completions`，模型名 `deepseek-flash`。Python 标准库直接发送 HTTPS 请求，不需要安装模型 SDK。正文作为文本块，校验后的 PNG/JPEG 图片转换为 Base64 data URL，放在 user 消息的 image_url 内容块中。具体接口格式参考 [官方视觉文档](https://api-docs.deepseek.com/guides/vision/)。服务支持范围可能比本项目宽；本项目的图片格式、数量和体积限制仍以本地代码为准。

请求采用 JSON 输出模式，同时用提示词约束字段，再执行本地结构与证据校验。JSON 格式正确不等于事实正确，故不能将模型返回直接认定为已核实。官方能力和参数应随版本复核，示例仓库不保证某个别名长期不变。

## 提取与防止编造

- 文章与图片文字属于不可信数据，提示词要求忽略其中的指令，不执行代码、工具或网页操作。
- 对活动名称、类别、主办单位、时间、地点、报名截止、报名方法、对象和简介进行结构化提取。
- 不能确认的字段用 null。日期缺少年份、相对日期或无法提供证据时不补全。
- 对非空字段检查证据是否出现在文章或模型整理的图片文字中；关键事实要求逐字摘录。摘要允许改写，仍需证据。
- 图片文字本身仍由模型识别，证据校验不能独立证明 OCR 正确；报告明确提示人工对照原文与海报。
- 未分析文章保留标题与原文链接，不能把“未分析”当成“不重要”。

手动图片功能与每日图文功能使用各自的结构化结果。成功分析不重复调用；历史文章不无条件重新分析。日任务的失败/中断结果保留供手动核对，不因超时推断“没有计费”。

## 费用与状态

公开配置默认关闭付费和每日自动分析。启用后按官方计费规则产生费用；最多调用次数是成本保护措施，不是固定金额保证。文章长度、图片与输出长度会影响消耗。原菜单5需要输入 ANALYZE，日任务则在用户主动启用后自动分析。

Key 只从 DEEPSEEK_API_KEY 读取。单请求和整体任务均有限时；每日调用次数计入失败/未知请求，跨重启保存。默认不自动重试付费请求，可选重试仅针对明确拒绝的限流/繁忙响应。认证失败、额度不足、网络故障与校验失败都不能伪造成分析成功。

部分分析失败仍生成 partial 日报，允许外部程序读取发送。真实请求、海报、结果和账单不放在公开仓库中；测试使用的模拟 JSON 不代表真实识别成功。
