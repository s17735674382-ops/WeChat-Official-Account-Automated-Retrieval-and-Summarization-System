# 云端部分：Wechat2RSS 与 Sealos Cloud 的技术方法

## 角色与边界

我在 Sealos Cloud 部署了 Wechat2RSS，Windows 客户端通过 HTTPS 读取订阅。云端完成公众号到 RSS 的转换，本地 Python 程序消费其输出。本仓库以文字记录这条技术路线，不分发 Wechat2RSS 软件、镜像、授权文件、登录会话或真实部署参数。

Wechat2RSS 私有部署涉及第三方软件授权，应自行查看其官方说明。云端部署不代表本项目实现了微信公众号官方接口，也不代表能绕过公众号访问限制。

## 可复现的方法

我的接入路径是：**Wechat2RSS 私有部署授权 → Sealos Cloud 容器服务 → 正常授权并添加公众号 → HTTPS RSS / OPML → 本地 Python 导入 → SQLite → 日报**。Wechat2RSS 不是本仓库的一部分；我建议先按其官方文档完成部署和单源验证，再接入本程序。不要直接照搬他人的服务域名、Token或账户配置。

1. 根据 Wechat2RSS 官方部署指南取得适当授权与镜像；在 Sealos 的应用部署界面创建容器应用。
2. 按服务文档设置监听端口、启动参数、持久化数据目录与运行资源。所需资源和数据挂载位置以选用版本的官方文档为准；本仓库没有导出真实云端配置，不声称已经验证某一 CPU/内存规格。
3. 在平台配置界面输入服务所需凭据，区分软件授权、管理认证、RSS访问控制与代理访问控制。变量名可以出现在文档中，真实值不进入源码或截图。
4. 配置 HTTPS 访问，检查服务健康与持久化是否正常。镜像升级前备份服务数据，避免重建后丢失订阅与授权状态。
5. 按官方使用指南完成必要的账户授权和公众号订阅。导出 OPML 后保存在客户端本地。
6. 客户端用 OPML 的 xmlUrl 导入订阅，不把订阅 URL 写死在 Python 中。优先使用 RSS 频道标题识别名称，缺失时采用待识别占位名称。
7. 先用一个已知有内容的源检查真实标题、正文、图片地址与原文链接，再扩大采集。空 RSS 只说明当前响应没有条目，不能证明全部文章已经被获取。

## 请求与隐私

本地程序的普通 RSS 和 Wechat2RSS 使用共同的公开网络请求检查：只允许 HTTP/HTTPS 标准端口，验证 DNS 与跳转目标，拒绝内网和本机目标。不自动对公众号发起批量网页抓取，不模拟微信登录，不执行网页 JavaScript。

RSS URL 本身可能包含 Token 或加密标识，因此 OPML、SQLite数据库及其备份均可能含敏感信息。只隐藏 API Key 远远不够；它们都应排除在 GitHub 外。本仓库也不提供真实服务域名、控制台地址、账号或授权邮箱。

服务端负责其自身更新频率，客户端的每天一次同步是另一层调度。源可能只保留有限篇文章，客户端不能恢复已经被源移除的历史内容。是否适合公开内容还取决于文章和图片的使用授权，本仓库仅发布程序与方法。
