# 如何设置自己的公众号订阅

公开仓库不包含项目使用者的订阅列表、公众号名称清单、真实RSS地址或OPML。每位使用者需要配置自己的订阅；下载代码不会自动获得原项目的公众号来源。

## 1. 在自己的 Wechat2RSS 服务添加公众号

先完成云端部署和软件授权，使用你自己的服务地址与管理认证登录。按照 [Wechat2RSS官方使用指南](https://wechat2rss.xlab.app/deploy/guide) 完成正常的账号授权；在服务的订阅管理中提交你准备关注的公众号的一篇真实文章链接，订阅成功后取得该公众号的RSS地址。操作名称可能随版本变化，以官方指南为准。

公众号文章网页地址与RSS订阅地址不是同一个东西。不要把文章链接直接填入本项目的RSS配置，也不要从仓库中寻找他人的账号、Cookie、Token或订阅地址。

先只添加一个你已确认近期有文章的公众号，在自己的服务中核实RSS确实有标题和条目，再逐步增加订阅。空RSS不等于“全部文章已采集”。

## 2. 导出并私下保存 OPML

从自己的订阅服务或订阅管理工具导出OPML，确认其中的订阅条目带有xmlUrl。实际可用的RSS地址必须来自你自己的服务，本文不提供公众号订阅地址示例。

建议保存在本地 `private/subscriptions.opml`。仓库忽略 `private/` 和所有OPML文件；不要强制将这些文件加入Git。OPML里的地址可能携带访问凭据，即使没有单独的password字段也不能公开。

## 3. 导入本地项目

第一次运行先复制示例配置：

```powershell
Copy-Item .\config.example.json .\config.json
python -B -X utf8 .\main.py
```

主菜单选 `8. Wechat2RSS采集`，再选 `1. 导入OPML`，填写你自己的OPML路径。重复导入相同地址不会重复新增订阅。

也可在项目目录执行：

```powershell
python -B -X utf8 .\main.py --import-opml '.\private\subscriptions.opml'
python -B -X utf8 .\main.py --list-sources
```

公众号名称优先从RSS频道标题识别；OPML和RSS都没有可用名称时显示待识别名称，不代表订阅是虚构的。订阅状态列表不显示完整RSS地址，以免泄露Token。导入结果保存在本地SQLite数据库，数据库也不能上传GitHub。

## 4. 先验证一个，再同步全部

菜单8选 `2. 只同步指定的一个公众号`，输入列表里的编号。对应命令示例：

```powershell
python -B -X utf8 .\main.py --sync-once --source-id 1
```

这里的1是本地订阅编号，不是公众号的公开账号ID。核对文章标题、发布时间、原文链接、正文与图片地址是否符合真实来源；菜单3可查看保存的文章。RSS只提供摘要时，本项目不能凭空补出全文。

确认后使用菜单8的全部同步，或：

```powershell
python -B -X utf8 .\main.py --sync-once
```

这两个同步命令只采集文章，不调用DeepSeek。`--daily-run` 才会在已开启付费设置时进入自动分析与日报流程。有关费用与计划任务，见主README。

## 5. 后续增加与排查

在自己的云端服务添加更多公众号，重新导出并导入OPML即可增加新订阅。导入是增量操作，不会因为新OPML少了某个条目，就自动删除本地已有订阅；本版本也不提供订阅一键清空。不要删除整个数据库来调整订阅，否则会丢失文章与分析记录。

如果地址无法访问，先检查自己的云端服务、授权与网络；不要在公开Issue粘贴完整RSS地址、OPML或数据库。需要描述问题时只提供错误类别、软件版本以及去掉所有令牌后的结构说明。公众号授权和访问限制应通过服务提供的正常流程处理，本项目不绕过验证或限制。
